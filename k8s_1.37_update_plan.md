# Kubernetes 1.37 Upgrade (cortex 0.46.0 / Butterfly) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Move Butterfly production from the `butterfly` cluster (EKS 1.34, cortex 0.45.0) to a new `butterfly2` cluster on EKS 1.37 built from cortex 0.46.0, before 1.34 leaves standard support on 2026-12-02.

**Architecture:** Same approach as the 1.31 and 1.34 rounds. Bump only what the Kubernetes version forces in cortex, rebuild all images, prove it on a throwaway `butterfly-dev` cluster, then create a second prod cluster next to the old one, switch the Route53 CNAME, run both for a few days, and tear the old one down.

**Tech Stack:** Go, eksctl, EKS (AL2023 AMIs), Istio, cluster-autoscaler (PEAT-AI fork with rate limiter), Docker/ECR, Route53.

**Spec:** Agreed in chat on 2026-11-10; summarised in "Agreed scope" below. Earlier rounds: `k8s_1.34_update.md`, `update_kubernetes_log.md`, `dev/versions.md`.

**Log:** `k8s_1.37_update.md` (repo root). Every task ends by appending what was done, what broke, and how it was fixed.

## Agreed scope

- Target EKS **1.37** (newest on EKS; standard support until 2027-12-01).
- Minimal bumps: only what 1.37 forces. Prometheus, Grafana, fluent-bit, NVIDIA device plugin, metrics-server, DCGM etc. stay unless they break.
- Image tag **0.46.0**.
- `butterfly-dev` first, then new prod cluster in parallel, DNS switch, old cluster kept a few days.
- New prod GPU nodegroup is created with `on_demand_base_capacity: 2` (replaces the hand-edited ASG setting from 2026-07-14).

## Review Focus

Failure modes most likely to bite, each pinned to a verification step below:

1. **eksctl 0.231.0 refuses `version: 1.37`** — its source only names versions up to 1.35 and looks newer ones up from AWS. → Task 2, Step 4 (dry run) proves it before anything else is built.
2. **Istio jumps four minors (1.27 → 1.31).** Last time a default change (`ENHANCED_RESOURCE_SCOPING`) stopped the ingress gateways getting certificates. → Task 5, Step 2 (read 1.28–1.31 upgrade notes) and Task 12, Step 3.
3. **cluster-autoscaler RBAC or flag drift on 1.37** → `forbidden` errors or a crash loop (this fork has a 210-restart history). → Task 7, Step 6 and Task 12, Step 4.
4. **GPU nodes on the 1.37 AL2023 nvidia AMI** — newer driver/containerd with the unchanged NVIDIA device plugin v0.15.0; nodes join but expose no `nvidia.com/gpu`, or Triton fails to load TensorRT engines. → Task 12, Steps 5 and 7.
5. **kube-proxy IPVS mode** — upstream has been deprecating IPVS since 1.35 (from memory, unverified). If `setup_ipvs` no longer yields `Using ipvs Proxier` on 1.37, services silently run in a different mode or kube-proxy fails. → Task 12, Step 2.
