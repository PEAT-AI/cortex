## 2026-11-10 — starting point and decisions

### why now
`butterfly` runs EKS 1.34. Standard support for 1.34 ends **2026-12-02**. The cluster's upgrade policy is `EXTENDED`, so it keeps running after that date but at the extended-support price.

```
aws eks describe-cluster-versions --region ap-south-1 --profile ml-admin
1.37  STANDARD_SUPPORT  default  standard until 2027-12-01
1.36  STANDARD_SUPPORT           standard until 2027-08-02
1.35  STANDARD_SUPPORT           standard until 2027-03-27
1.34  STANDARD_SUPPORT           standard until 2026-12-02
1.33  EXTENDED_SUPPORT
```

Note for the cadence: each EKS version gets ~14 months of standard support. 1.37 covers us until 2027-12-01, so the next round has to start around October 2027, not in 18 months.

### which version
**1.37.** It is the newest on EKS (released there 2026-10-01). Kubernetes 1.38 is only a beta upstream (final planned 2026-12-16), so EKS won't have it before roughly Jan/Feb 2027; waiting would mean two months at the extended price.

AL2023 nvidia AMI for 1.37 exists in ap-south-1: `amazon-eks-node-al2023-x86_64-nvidia-1.37-v20261107`.

### decisions
- Same procedure as before: bump cortex, build images, test on `butterfly-dev`, create a second prod cluster, switch Route53, keep the old one a few days.
- New prod cluster is called `butterfly2` (old one is `butterfly`).
- New prod GPU nodegroup gets `on_demand_base_capacity: 2` at creation. This replaces the ASG edit done by hand on 2026-07-14, which cortex could not manage on a running nodegroup.
- While both prod clusters run we pay for two extra on-demand g4dn.xlarge outside the Savings Plan, about $28/day.
- Go modules: bump in place with `go get` instead of deleting go.mod (that was the part that got stuck last time).
- Autoscaler fork: cherry-pick the three cortex commits (517210866, 988a23557, f584ab358) onto the upstream 1.37.0 tag instead of reset/stash.
- Claude does code, tests and local builds alone; stops for a go-ahead before pushing the autoscaler branch, pushing images, creating a cluster, switching DNS, deleting a cluster.

## 2026-11-10 — Task 1: branch and baseline

- branch `k8s_1.37_update` created from `plantix`.
- `make test` failed before any change (exit 126):
  `testbin/bin/kube-apiserver: cannot execute binary file: Exec format error`
  - `build/test.sh` downloads "envtest" tools (kube-apiserver/etcd 1.19.2) into `testbin/` before running go tests.
  - the binaries in `testbin/` and `testbin_old/` are corrupt: all NUL bytes are stripped out of them (ELF header starts `7f454c46 0201 0102 3e01` instead of `7f454c46 0201 0100 0000...`). Both dirs are dated 2025-11-12, the day of the "search & replace 0.45.0 everywhere" step last round — most likely a replace tool ran over binary files. `testbin/` is git-ignored, so nothing tracked was hurt.
  - re-downloading is not possible either: `storage.googleapis.com/kubebuilder-tools/...` now returns 403.
  - the only test that would use these tools (`pkg/crds/controllers/batch/suite_test.go`) is completely commented out.
  - fix: removed the envtest setup lines from `build/test.sh`. `testbin/` and `testbin_old/` can be deleted by hand.
- after the fix `make test` passes: 20 packages ok, "go tests passed".
- lesson for the 0.46.0 search & replace: restrict it to text files (`grep -rIl ... | xargs sed -i`), never run it over a whole tree.
